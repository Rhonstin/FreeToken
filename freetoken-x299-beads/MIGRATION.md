# Перехід v1 -> v2

Не імпортуйте v2 як другий паралельний epic, якщо вже працює v1. `migration-map.json` відображає 01 -> 01a/01b тощо. Старі task markdown замінені новими; при розпакуванні поверх каталогу старі файли можуть залишитися, але manifest їх не використовує.

Якщо v1 НЕ імпортований: звичайний `import_beads.py --apply` створює 40 tasks.

Якщо v1 імпортований: збережіть `.import-state.json`; імпортер зупиниться на version mismatch. Не видаляйте його для обходу перевірки. Агент має через `bd show` перевірити кожний старий ID та evidence. Завершені задачі не відкривати автоматично й не дублювати: додати лише відсутні a/b contracts як follow-up. Для незавершених — створити a/b subtasks у наявному epic, зв’язати blockers за manifest, перенести контекст/посилання, позначити стару задачу superseded лише після перевірки перенесення. Виконати через підтримувані вашою версією bd create/update/dep команди після bd prime; універсальний автоматичний migrator тут не заявлений.

Не змінювати статуси без actual evidence і не губити старі IDs. Commit/push/Dolt remote sync не є частиною міграції.
