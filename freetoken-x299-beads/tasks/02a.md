# 02a. Закріпити checkpoint Qwen3.8 та бюджет RAM/VRAM — контракт і fixtures

Версія плану: 2. Стара задача: 02.

## Вхідні умови

config.json; tensor metadata; target/draft shapes/dtypes; PLE extents; current Beads status.

## Контракт

Byte ledger: unique storages, fixed/variable, host/device, peak/steady; shared tensors не дублювати.

## Покрокове виконання

1. Зібрати inputs нижче; невідомі поля залишити null із reason, не підставляти guesses.
2. Прочитати поточні symbols у вказаних файлах; порівняти з baseline SHA. За drift оновити contract, не застосовувати старі hunks.
3. Створити contract.json за CONTRACTS.md: scope, baseline, fields, invariants, cases, commands, expected outcomes.
4. Описати кожний negative case як fixture: given/when/then, exact assertions; valid/invalid cases розділити.
5. Зібрати baseline/reproduction evidence до production code edit. Hardware відсутній — заблокувати лише необхідну hardware частину.
6. Зафіксувати bounded candidate set, numerical tolerances і performance metric до вимірів. Передати артефакти задачі b.

## Обов’язкові негативні сценарії

- відсутні mtp weights.
- mixed formats.
- FTW посилається на відсутній PLE.
- peak RAM > available.
- невідомий token template.

## Stop conditions

Зупинити запуск, якщо metadata load не узгоджується з checkpoint. Не конвертувати модель або format автоматично, щоб приховати fit failure.

## Артефакти

У `evidence/x299/02a/`: contract.json, commands.json, result.json і raw logs. Для a result.outcome=contract_ready; для b implemented/no_change/blocked. Actual raw measurement paths мають існувати. Усі статуси в Beads.

```bash

Якщо weights не вміщуються — checkpoint-selection gate з quality baseline, а не мовчазна підміна моделі. Availability MTP weights перевірена.
