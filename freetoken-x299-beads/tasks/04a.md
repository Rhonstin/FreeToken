# 04a. Профілювати критичний шлях одного decode step — контракт і fixtures

Версія плану: 2. Стара задача: 04.

## Вхідні умови

короткий opt-in trace, GPU events, per-layer counters, uninstrumented repeats.

## Контракт

Counters per run/context/phase; exposed time від critical path, не сума overlapped ranges.

## Покрокове виконання

1. Зібрати inputs нижче; невідомі поля залишити null із reason, не підставляти guesses.
2. Прочитати поточні symbols у вказаних файлах; порівняти з baseline SHA. За drift оновити contract, не застосовувати старі hunks.
3. Створити contract.json за CONTRACTS.md: scope, baseline, fields, invariants, cases, commands, expected outcomes.
4. Описати кожний negative case як fixture: given/when/then, exact assertions; valid/invalid cases розділити.
5. Зібрати baseline/reproduction evidence до production code edit. Hardware відсутній — заблокувати лише необхідну hardware частину.
6. Зафіксувати bounded candidate set, numerical tolerances і performance metric до вимірів. Передати артефакти задачі b.

## Обов’язкові негативні сценарії

- overlap CPU/DMA.
- profiler додає sync.
- empty batch.
- counter overflow/reset.
- error під sampling.

## Stop conditions

Не додавати synchronize per layer у production. Profiler overhead >2% — speed report лише з uninstrumented runs.

## Артефакти

У `evidence/x299/04a/`: contract.json, commands.json, result.json і raw logs. Для a result.outcome=contract_ready; для b implemented/no_change/blocked. Actual raw measurement paths мають існувати. Усі статуси в Beads.

## Конкретні команди

```bash
bd show <actual-bead-id>
uv run pytest --collect-only -q <existing-test-paths-from-contract>
uv run pytest -q <existing-test-paths-from-contract> -m "not slow"
```

Кутові параметри — не runnable literals: задача a замінює їх реальними знайденими шляхами. Для inventory/benchmark-only задач pytest=N/A із reason, а acceptance перевіряється даними; це не test passed. Повні executable argv зберігати в commands.json.

## Критерій закриття цієї фази

Усі fixtures мають expected results, inputs перевірені, contract і baseline артефакти існують; production code не змінений.

## Робота

Додати opt-in sampled ranges/counters для GPU compute, expert H2D, CPU GEMV, waits, routing/cache misses, PLE D2H/read/H2D, QSA, GDN, sampling і Python launch. Використати наявні offload stats. Зробити кілька representative traces і uninstrumented repeats. Визначити bytes per committed token та час exposed stalls, не підсумовувати overlapped ranges як serial time.

## Критерії приймання

Bottleneck report пояснює p95 і середній TPOT для short/long context. Профілювання вимкнене за замовчуванням; overhead виміряний. Кожна подальша optimization task має trace evidence або завершується ADR no-change з доказами.
