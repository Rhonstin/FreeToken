## Вхідні умови

resolved CLI/backend matrix; baseline command; bounded candidate list.

## Контракт

Candidate IDs, argv arrays, one-factor stages; final combined winner ретестувати.

## Покрокове виконання

1. Зібрати inputs нижче; невідомі поля залишити null із reason, не підставляти guesses.
2. Прочитати поточні symbols у вказаних файлах; порівняти з baseline SHA. За drift оновити contract, не застосовувати старі hunks.
3. Створити contract.json за CONTRACTS.md: scope, baseline, fields, invariants, cases, commands, expected outcomes.
4. Описати кожний negative case як fixture: given/when/then, exact assertions; valid/invalid cases розділити.
5. Зібрати baseline/reproduction evidence до production code edit. Hardware відсутній — заблокувати лише необхідну hardware частину.
6. Зафіксувати bounded candidate set, numerical tolerances і performance metric до вимірів. Передати артефакти задачі b.

## Обов’язкові негативні сценарії

- invalid backend.
- unsupported weight format.
- max-fetch > misses.
- OOM.
- hidden fallback.
- graph capture failure.

## Stop conditions

Будь-який fallback записати effective configuration і не називати requested candidate успішним.

## Робота

Послідовний bounded sweep: offload baseline, hybrid із max-fetch auto/0/1/2 та релевантними межами misses, CPU лише якщо формат підтримується; --moe-cpu-layers subsets тільки після вимірів. Graph 0/1 для single-request. Фіксувати expert slots, KV, PLE і sampling, міняти один фактор. Перевіряти parser/backend capabilities: NVFP4 storage не означає native Blackwell kernels на 3090.

## Критерії приймання

Вибрані best-known профілі для 4K/16K/32K із confidence/noise. Auto не визнаний найкращим лише за microbenchmark. Unsupported combinations відхилені, помилки не приховані fallback. Точні команди записані; жодного придуманого universal slots/thread count.
