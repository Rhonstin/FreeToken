# 06b. CPU thread/affinity/ISA tuning для конкретного i7 — виконання та приймання

Версія плану: 2. Стара задача: 06.

## Вхідні умови

physical cores within process affinity, CPUID flags, effective clocks.

## Контракт

One worker/core first; coordinator і engine не на тому ж busy-spin core без вимірів.

## Покрокове виконання

1. Прочитати завершений contract задачі a та перевірити evidence SHA/hardware fingerprint.
2. Виконати базову діагностику/experiment за contract. Для optimization без bottleneck evidence завершити no-change ADR, не писати speculative code.
3. Змінити лише узгоджені interfaces/files. Інший subsystem виявився необхідним — створити blocker bead, не розширювати scope мовчки.
4. Запустити positive і negative fixtures із задачі a та релевантні існуючі regression tests. Для bug спочатку red на baseline, потім green.
5. Запустити paired uninstrumented A/B за RUNBOOK.md; raw rows не редагувати. OOM/error/skipped окремо, а не в mean.
6. Перевірити rollback до baseline/default і повторний запуск. Заповнити result.json, no-change ADR за потреби.
7. Закрити bead тільки після GATES.md. У handoff вказати exact command, exit code, artifact SHA, limitations і actual next ready ID.

## Обов’язкові негативні сценарії

- SMT siblings.
- uneven cpuset.
- request > allowed CPUs.
- no AVX512.
- CPU freq drops under AVX512.
- PLE steals cores.

## Stop conditions

AVX512 порівнювати лише при flags і explicit compiled support. Oversubscribed candidate не застосовувати як default.

## Детальна постановка батьківської задачі

# 06. CPU thread/affinity/ISA tuning для конкретного i7

## Робота

Використати existing physical_core_cpus/resolve_threads_and_affinity. Sweep 1/2/4/... до physical cores, окремо SMT, залишаючи ресурси scheduler і PLE I/O. Звірити --isa help і реальну C++ dispatch підтримку. AVX-512 порівнювати з AVX2 лише якщо CPU/збірка підтримують, із effective clock і sustained throttling. Виміряти одночасний CPU GEMV і DMA на DDR4-2133.

## Критерії приймання

Рекомендація спирається на full-model TPOT, а не STREAM alone. Немає oversubscription/spin starvation. Unsupported ISA не виконується. Коригувати auto threads лише за стійких даних, explicit user setting має пріоритет.
