# 09a. Калібрувати hybrid split за реальним часом експертів — контракт і fixtures

Версія плану: 2. Стара задача: 09.

## Вхідні умови

miss histogram + measured CPU/gather overlap за expert shapes.

## Контракт

Discrete bounded actions; min 32 observations; hold 32 steps; deterministic fallback; these are initial tuning constants.

## Покрокове виконання

1. Зібрати inputs нижче; невідомі поля залишити null із reason, не підставляти guesses.
2. Прочитати поточні symbols у вказаних файлах; порівняти з baseline SHA. За drift оновити contract, не застосовувати старі hunks.
3. Створити contract.json за CONTRACTS.md: scope, baseline, fields, invariants, cases, commands, expected outcomes.
4. Описати кожний negative case як fixture: given/when/then, exact assertions; valid/invalid cases розділити.
5. Зібрати baseline/reproduction evidence до production code edit. Hardware відсутній — заблокувати лише необхідну hardware частину.
6. Зафіксувати bounded candidate set, numerical tolerances і performance metric до вимірів. Передати артефакти задачі b.

## Обов’язкові негативні сценарії

- zero misses.
- all hits.
- CPU unavailable.
- noisy samples.
- missing metrics.
- policy oscillates.
- very short request.

## Stop conditions

За noisy/no gain залишити best static configuration. Заборонено змінювати decision кожного шару з synchronous readback.

## Артефакти

У `evidence/x299/09a/`: contract.json, commands.json, result.json і raw logs. Для a result.outcome=contract_ready; для b implemented/no_change/blocked. Actual raw measurement paths мають існувати. Усі статуси в Beads.

## Критерій закриття цієї фази

Усі fixtures мають expected results, inputs перевірені, contract і baseline артефакти існують; production code не змінений.

## Робота

Поточна overlap bandwidth fraction — стартова оцінка. Додати cost calibration на actual expert geometry/miss count, fixed launch/sync cost, CPU contention і hit rate. Оцінювати max(T_gpu+exposed_transfer,T_cpu)+coordination, а не ideal bandwidth ratio. Опційний bounded adaptive max-fetch з hysteresis, sampled feedback і ручним override.

## Критерії приймання

Порівняння static best vs adaptive на unseen prompts показує benefit понад noise або ADR відхиляє зміну. Немає policy oscillation, graph-invalid allocations, host sync per layer. Offload fallback при відсутніх/невалідних даних.
