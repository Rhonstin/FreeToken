# 09b. Калібрувати hybrid split за реальним часом експертів — виконання та приймання

Версія плану: 2. Стара задача: 09.

## Вхідні умови

miss histogram + measured CPU/gather overlap за expert shapes.

## Контракт

Discrete bounded actions; min 32 observations; hold 32 steps; deterministic fallback; these are initial tuning constants.

## Покрокове виконання

1. Прочитати завершений contract задачі a та перевірити evidence SHA/hardware fingerprint.
2. Виконати базову діагностику/experiment за contract. Для optimization без bottleneck evidence завершити no-change ADR, не писати speculative code.
3. Змінити лише узгоджені interfaces/files. Інший subsystem виявився необхідним — створити blocker bead, не розширювати scope мовчки.
4. Запустити positive і negative fixtures із задачі a та релевантні існуючі regression tests. Для bug спочатку red на baseline, потім green.
5. Запустити paired uninstrumented A/B за RUNBOOK.md; raw rows не редагувати. OOM/error/skipped окремо, а не в mean.
6. Перевірити rollback до baseline/default і повторний запуск. Заповнити result.json, no-change ADR за потреби.
7. Закрити bead тільки після GATES.md. У handoff вказати exact command, exit code, artifact SHA, limitations і actual next ready ID.

## Обов’язкові негативні сценарії

- zero misses.
- all hits.
- CPU unavailable.
- noisy samples.
- missing metrics.
- policy oscillates.
- very short request.

## Stop conditions

За noisy/no gain залишити best static configuration. Заборонено змінювати decision кожного шару з synchronous readback.

## Артефакти

У `evidence/x299/09b/`: contract.json, commands.json, result.json і raw logs. Для a result.outcome=contract_ready; для b implemented/no_change/blocked. Actual raw measurement paths мають існувати. Усі статуси в Beads.

## Конкретні команди

```bash
bd show <actual-bead-id>
uv run pytest --collect-only -q <existing-test-paths-from-contract>
uv run pytest -q <existing-test-paths-from-contract> -m "not slow"
```

Кутові параметри — не runnable literals: задача a замінює їх реальними знайденими шляхами. Для inventory/benchmark-only задач pytest=N/A із reason, а acceptance перевіряється даними; це не test passed. Повні executable argv зберігати в commands.json.

## Критерій закриття цієї фази

Усі критерії нижче та GATES.md пройдені; no-change має виміри й причину; missing hardware не вважається no-change.

## Детальна постановка батьківської задачі

# 09. Калібрувати hybrid split за реальним часом експертів

## Робота

Поточна overlap bandwidth fraction — стартова оцінка. Додати cost calibration на actual expert geometry/miss count, fixed launch/sync cost, CPU contention і hit rate. Оцінювати max(T_gpu+exposed_transfer,T_cpu)+coordination, а не ideal bandwidth ratio. Опційний bounded adaptive max-fetch з hysteresis, sampled feedback і ручним override.

## Критерії приймання

Порівняння static best vs adaptive на unseen prompts показує benefit понад noise або ADR відхиляє зміну. Немає policy oscillation, graph-invalid allocations, host sync per layer. Offload fallback при відсутніх/невалідних даних.
