# 10a. Покращити cache admission лише за routing traces — контракт і fixtures

Версія плану: 2. Стара задача: 10.

## Вхідні умови

offline trace replay with same cache slots and byte budget.

## Контракт

Policy module independent from weight math; fixed capacity; counters for reject/evict/hit.

## Покрокове виконання

1. Зібрати inputs нижче; невідомі поля залишити null із reason, не підставляти guesses.
2. Прочитати поточні symbols у вказаних файлах; порівняти з baseline SHA. За drift оновити contract, не застосовувати старі hunks.
3. Створити contract.json за CONTRACTS.md: scope, baseline, fields, invariants, cases, commands, expected outcomes.
4. Описати кожний negative case як fixture: given/when/then, exact assertions; valid/invalid cases розділити.
5. Зібрати baseline/reproduction evidence до production code edit. Hardware відсутній — заблокувати лише необхідну hardware частину.
6. Зафіксувати bounded candidate set, numerical tolerances і performance metric до вимірів. Передати артефакти задачі b.

## Обов’язкові негативні сценарії

- all unique experts.
- alternating layer working sets.
- pin/in-flight victim.
- reset/rebuild.
- adversarial thrashing.

## Stop conditions

Не міняти router або skip experts. Reuse existing ownership invariants; default LRU survives unsupported trace.

## Детальна постановка батьківської задачі

# 10. Покращити cache admission лише за routing traces

## Робота

Поточна policy LRU. Зняти per-layer expert locality/miss-size traces на code/chat/retrieval. Offline replay порівнює LRU із frequency+recency admission або layer quotas. Одна bounded опція після evidence; не змінювати router/top-k і не пропускати потрібні експерти. GPU residency hot experts зберігає ownership/in-flight ordering.

## Критерії приймання

Trace replay і live A/B підтверджують менше exposed PCIe time, а не тільки більше hits. Після eviction/reset немає stale expert weights. Default LRU і deterministic fallback збережені. Якщо locality не дає виграшу — no-change висновок.
