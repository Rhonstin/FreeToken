# 10b. Покращити cache admission лише за routing traces — виконання та приймання

Версія плану: 2. Стара задача: 10.

## Вхідні умови

offline trace replay with same cache slots and byte budget.

## Контракт

Policy module independent from weight math; fixed capacity; counters for reject/evict/hit.

## Покрокове виконання

1. Прочитати завершений contract задачі a та перевірити evidence SHA/hardware fingerprint.
2. Виконати базову діагностику/experiment за contract. Для optimization без bottleneck evidence завершити no-change ADR, не писати speculative code.
3. Змінити лише узгоджені interfaces/files. Інший subsystem виявився необхідним — створити blocker bead, не розширювати scope мовчки.
4. Запустити positive і negative fixtures із задачі a та релевантні існуючі regression tests. Для bug спочатку red на baseline, потім green.
5. Запустити paired uninstrumented A/B за RUNBOOK.md; raw rows не редагувати. OOM/error/skipped окремо, а не в mean.
6. Перевірити rollback до baseline/default і повторний запуск. Заповнити result.json, no-change ADR за потреби.
7. Закрити bead тільки після GATES.md. У handoff вказати exact command, exit code, artifact SHA, limitations і actual next ready ID.

## Обов’язкові негативні сценарії

- all unique experts.
- alternating layer working sets.
- pin/in-flight victim.
- reset/rebuild.
- adversarial thrashing.

## Stop conditions

Не міняти router або skip experts. Reuse existing ownership invariants; default LRU survives unsupported trace.

## Артефакти

У `evidence/x299/10b/`: contract.json, commands.json, result.json і raw logs. Для a result.outcome=contract_ready; для b implemented/no_change/blocked. Actual raw measurement paths мають існувати. Усі статуси в Beads.

## Критерій закриття цієї фази

Усі критерії нижче та GATES.md пройдені; no-change має виміри й причину; missing hardware не вважається no-change.

## Детальна постановка батьківської задачі

# 10. Покращити cache admission лише за routing traces

## Робота

Поточна policy LRU. Зняти per-layer expert locality/miss-size traces на code/chat/retrieval. Offline replay порівнює LRU із frequency+recency admission або layer quotas. Одна bounded опція після evidence; не змінювати router/top-k і не пропускати потрібні експерти. GPU residency hot experts зберігає ownership/in-flight ordering.

## Критерії приймання

Trace replay і live A/B підтверджують менше exposed PCIe time, а не тільки більше hits. Після eviction/reset немає stale expert weights. Default LRU і deterministic fallback збережені. Якщо locality не дає виграшу — no-change висновок.
