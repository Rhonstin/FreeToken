## Детальна постановка батьківської задачі

# 13. PLE I/O overlap і thread-pool tuning

## Робота

Аудит existing graph flag-sync/readback event у host_fill_batch. Sweep I/O worker count/queue depth на фактичному storage з active CPU-MoE; не фіксувати 16 threads на будь-якому i7. Для prefill групувати відомі rows; decode дотримується sampling dependency. Bounded staging slots тільки з явними completion events; зменшити Python allocation/tolist якщо trace це виправдовує.

## Критерії приймання

Немає deadlock, stale staging або неправильних rows при prefix hit, cancellation, partial speculative accept і error signal. Graph і eager output parity. P95 PLE wait покращився без втрати CPU GEMV bandwidth чи росту RAM без меж.
