# 14a. Ampere kernel tuning для QSA/GDN і MoE — контракт і fixtures

Версія плану: 2. Стара задача: 14.

## Вхідні умови

actual head dims, tile/register profile, supported backend registry.

## Контракт

Specialization keys=(SM, dtype, shape, format); fallback preserved; tune one kernel family at a time.

## Покрокове виконання

1. Зібрати inputs нижче; невідомі поля залишити null із reason, не підставляти guesses.
2. Прочитати поточні symbols у вказаних файлах; порівняти з baseline SHA. За drift оновити contract, не застосовувати старі hunks.
3. Створити contract.json за CONTRACTS.md: scope, baseline, fields, invariants, cases, commands, expected outcomes.
4. Описати кожний negative case як fixture: given/when/then, exact assertions; valid/invalid cases розділити.
5. Зібрати baseline/reproduction evidence до production code edit. Hardware відсутній — заблокувати лише необхідну hardware частину.
6. Зафіксувати bounded candidate set, numerical tolerances і performance metric до вимірів. Передати артефакти задачі b.

## Обов’язкові негативні сценарії

- non-power-of-two supported dims.
- padded batch.
- zero length.
- different strides.
- long context split boundaries.

## Stop conditions

Do not borrow H100 tuning. Register/shared memory and launch limits measured on SM86; code changes require correctness first.

## Детальна постановка батьківської задачі

# 14. Ampere kernel tuning для QSA/GDN і MoE

## Робота

Profile top kernels для batch=1 та довгого контексту. Порівняти лише доступні SM86 quant backends; Marlin/Triton перевірити на exact checkpoint, b12x/native FP8 не припускати. Tuning split-K, tile sizes, num_warps за head dimensions Qwen; fusion лише для доведеного launch/memory bottleneck. Не використовувати H100 autotune config як profile 3090.

## Критерії приймання

Чисельні reference tests QSA/GDN/MoE проходять, graph replay стабільний. JIT keys включають device/geometry. Microkernel speedup підтверджений full-model accepted tok/s. Не змінювати precision/router/attention selection мовчки.
