# 14b. Ampere kernel tuning для QSA/GDN і MoE — виконання та приймання

Версія плану: 2. Стара задача: 14.

## Вхідні умови

actual head dims, tile/register profile, supported backend registry.

## Контракт

Specialization keys=(SM, dtype, shape, format); fallback preserved; tune one kernel family at a time.

## Покрокове виконання

1. Прочитати завершений contract задачі a та перевірити evidence SHA/hardware fingerprint.
2. Виконати базову діагностику/experiment за contract. Для optimization без bottleneck evidence завершити no-change ADR, не писати speculative code.
3. Змінити лише узгоджені interfaces/files. Інший subsystem виявився необхідним — створити blocker bead, не розширювати scope мовчки.
4. Запустити positive і negative fixtures із задачі a та релевантні існуючі regression tests. Для bug спочатку red на baseline, потім green.
5. Запустити paired uninstrumented A/B за RUNBOOK.md; raw rows не редагувати. OOM/error/skipped окремо, а не в mean.
6. Перевірити rollback до baseline/default і повторний запуск. Заповнити result.json, no-change ADR за потреби.
7. Закрити bead тільки після GATES.md. У handoff вказати exact command, exit code, artifact SHA, limitations і actual next ready ID.

## Обов’язкові негативні сценарії

- non-power-of-two supported dims.
- padded batch.
- zero length.
- different strides.
- long context split boundaries.

## Stop conditions

Do not borrow H100 tuning. Register/shared memory and launch limits measured on SM86; code changes require correctness first.

## Артефакти

У `evidence/x299/14b/`: contract.json, commands.json, result.json і raw logs. Для a result.outcome=contract_ready; для b implemented/no_change/blocked. Actual raw measurement paths мають існувати. Усі статуси в Beads.

```bash

uv run pytest -q <existing-test-paths-from-contract> -m "not slow"
```

Кутові параметри — не runnable literals: задача a замінює їх реальними знайденими шляхами. Для inventory/benchmark-only задач pytest=N/A із reason, а acceptance перевіряється даними; це не test passed. Повні executable argv зберігати в commands.json.

## Критерій закриття цієї фази

Усі критерії нижче та GATES.md пройдені; no-change має виміри й причину; missing hardware не вважається no-change.

## Детальна постановка батьківської задачі

# 14. Ampere kernel tuning для QSA/GDN і MoE

## Робота

Profile top kernels для batch=1 та довгого контексту. Порівняти лише доступні SM86 quant backends; Marlin/Triton перевірити на exact checkpoint, b12x/native FP8 не припускати. Tuning split-K, tile sizes, num_warps за head dimensions Qwen; fusion лише для доведеного launch/memory bottleneck. Не використовувати H100 autotune config як profile 3090.

## Критерії приймання

Чисельні reference tests QSA/GDN/MoE проходять, graph replay стабільний. JIT keys включають device/geometry. Microkernel speedup підтверджений full-model accepted tok/s. Не змінювати precision/router/attention selection мовчки.
