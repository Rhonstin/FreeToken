# 15b. Приймання існуючого MTP: correctness і повний cost — виконання та приймання

Версія плану: 2. Стара задача: 15.

## Вхідні умови

draft checkpoint schema, budget, existing spec unit tests, no-spec reference.

## Контракт

committed prefix invariant across host tokens/device tokens/KV/recurrent state/counters.

## Покрокове виконання

1. Прочитати завершений contract задачі a та перевірити evidence SHA/hardware fingerprint.
2. Виконати базову діагностику/experiment за contract. Для optimization без bottleneck evidence завершити no-change ADR, не писати speculative code.
3. Змінити лише узгоджені interfaces/files. Інший subsystem виявився необхідним — створити blocker bead, не розширювати scope мовчки.
4. Запустити positive і negative fixtures із задачі a та релевантні існуючі regression tests. Для bug спочатку red на baseline, потім green.
5. Запустити paired uninstrumented A/B за RUNBOOK.md; raw rows не редагувати. OOM/error/skipped окремо, а не в mean.
6. Перевірити rollback до baseline/default і повторний запуск. Заповнити result.json, no-change ADR за потреби.
7. Закрити bead тільки після GATES.md. У handoff вказати exact command, exit code, artifact SHA, limitations і actual next ready ID.

## Обов’язкові негативні сценарії

- accept 0/partial/all.
- EOS inside proposal.
- max length.
- stochastic reject.
- cancellation.
- QSA/GDN/PLE rollback.

## Stop conditions

Якщо any state oracle fails — MTP off і bug bead. No speed acceptance before correctness.

## Артефакти

У `evidence/x299/15b/`: contract.json, commands.json, result.json і raw logs. Для a result.outcome=contract_ready; для b implemented/no_change/blocked. Actual raw measurement paths мають існувати. Усі статуси в Beads.


Кутові параметри — не runnable literals: задача a замінює їх реальними знайденими шляхами. Для inventory/benchmark-only задач pytest=N/A із reason, а acceptance перевіряється даними; це не test passed. Повні executable argv зберігати в commands.json.

## Критерій закриття цієї фази

# 15. Приймання існуючого MTP: correctness і повний cost

## Робота

MTP head/driver уже є: не створювати заново. Перевірити точний checkpoint, dedicated BF16 draft expert banks і додаткові RAM/VRAM/PCIe витрати. MTP off vs depths 1/2/3, adaptive off спочатку. Exact verify/commit/rollback тестувати для greedy/stochastic, rejection всіх/частини/жодного, EOS, stop і length bounds. QSA/GDN/PLE state повинен відповідати committed prefix.

## Критерії приймання

Звіти: draft time, target verify time, accepted drafts, emitted committed tokens, rollback/replay time, expert traffic та memory. Greedy parity і stochastic verification invariants. Не вважати acceptance rate доказом speedup. Якщо fit/correctness gate не пройдено — MTP залишається вимкнений.
