Версія плану: 2. Стара задача: 17.

## Вхідні умови

request-local ngram candidates and verified continuation.

## Контракт

Candidate tokens not emitted before verification; cap search work and proposal length separately.

## Покрокове виконання

1. Зібрати inputs нижче; невідомі поля залишити null із reason, не підставляти guesses.
2. Прочитати поточні symbols у вказаних файлах; порівняти з baseline SHA. За drift оновити contract, не застосовувати старі hunks.
3. Створити contract.json за CONTRACTS.md: scope, baseline, fields, invariants, cases, commands, expected outcomes.
4. Описати кожний negative case як fixture: given/when/then, exact assertions; valid/invalid cases розділити.
5. Зібрати baseline/reproduction evidence до production code edit. Hardware відсутній — заблокувати лише необхідну hardware частину.
6. Зафіксувати bounded candidate set, numerical tolerances і performance metric до вимірів. Передати артефакти задачі b.

## Обов’язкові негативні сценарії

- no repeat.
- huge repeat.
- suffix overlap.
- cross-request same text.
- EOS.
- timeout.
- MTP flag simultaneously set.

## Stop conditions

Mutual exclusion enforced. No cross-request token leakage. Worst-case lookup bounded before optimization acceptance.

## Робота

У fork є --lookup-draft/--lookup-ngram; він mutually exclusive з MTP. Порівняти off/lookup/MTP на code editing, повторюваному тексті та nonrepetitive controls. Урахувати lookup CPU cost, verify/replay і expanded KV/state reservations: no draft weights не означає zero runtime overhead.

## Критерії приймання

Ті самі exact verify gates; accepted output tok/s і p95 покращуються на заявленому workload або lookup залишається off. Worst-case lookup bounded; request isolation і cancellation перевірені. Не ввімкнути lookup і MTP разом.
