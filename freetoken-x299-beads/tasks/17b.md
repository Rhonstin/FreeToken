# 17b. Оцінити prompt lookup як дешевшу speculation — виконання та приймання

Версія плану: 2. Стара задача: 17.

## Вхідні умови

request-local ngram candidates and verified continuation.

## Контракт

Candidate tokens not emitted before verification; cap search work and proposal length separately.

## Покрокове виконання

1. Прочитати завершений contract задачі a та перевірити evidence SHA/hardware fingerprint.
2. Виконати базову діагностику/experiment за contract. Для optimization без bottleneck evidence завершити no-change ADR, не писати speculative code.
3. Змінити лише узгоджені interfaces/files. Інший subsystem виявився необхідним — створити blocker bead, не розширювати scope мовчки.
4. Запустити positive і negative fixtures із задачі a та релевантні існуючі regression tests. Для bug спочатку red на baseline, потім green.
5. Запустити paired uninstrumented A/B за RUNBOOK.md; raw rows не редагувати. OOM/error/skipped окремо, а не в mean.
6. Перевірити rollback до baseline/default і повторний запуск. Заповнити result.json, no-change ADR за потреби.
7. Закрити bead тільки після GATES.md. У handoff вказати exact command, exit code, artifact SHA, limitations і actual next ready ID.

## Обов’язкові негативні сценарії

- no repeat.
- huge repeat.
- suffix overlap.
- cross-request same text.
- EOS.
- timeout.
- MTP flag simultaneously set.

## Stop conditions

Mutual exclusion enforced. No cross-request token leakage. Worst-case lookup bounded before optimization acceptance.

## Робота

У fork є --lookup-draft/--lookup-ngram; він mutually exclusive з MTP. Порівняти off/lookup/MTP на code editing, повторюваному тексті та nonrepetitive controls. Урахувати lookup CPU cost, verify/replay і expanded KV/state reservations: no draft weights не означає zero runtime overhead.

## Критерії приймання

Ті самі exact verify gates; accepted output tok/s і p95 покращуються на заявленому workload або lookup залишається off. Worst-case lookup bounded; request isolation і cancellation перевірені. Не ввімкнути lookup і MTP разом.
